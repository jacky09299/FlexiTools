如何貢獻

感謝您有興趣為 FlexiTools 做出貢獻！我們歡迎所有形式的貢獻，從錯誤回報到新功能模組的開發。

開發入門

開始之前，請確保您的開發環境已準備就緒。FlexiTools 主要使用 Python 和 Tkinter GUI 工具包構建。

主要依賴套件

請確保您已安裝以下核心套件。某些模組可能需要額外的特定套件。

  • pandas - 用於數據處理，例如在 plot_gui 和 report 模組中。
  • matplotlib - 用於數據可視化，是 plot_gui 的核心。
  • PyPDF2 - 用於 PDF 操作，例如在 pdf_processor 模組中。
  • moviepy & opencv-python - 用於影片處理。
  • rembg - 用於圖片去背。
  • cefpython3 - browser 模組的網頁渲染核心。
  • psutil - 用於 system_info 模組獲取系統資訊。
  • pygame - 用於音訊播放。
  • pyroomacoustics - 用於音訊效果模擬。
  • yt-dlp - 用於 YouTube 下載功能。

您可以使用 pip 來安裝這些套件：

pip install pandas matplotlib PyPDF2 moviepy opencv-python rembg cefpython3 psutil pygame pyroomacoustics yt-dlp

提示

專案中的 check_imports.py 腳本提供了一個方便的方式來檢查和模擬缺失的依賴，有助於在不完全安裝所有套件的情況下運行主應用程式。

創建一個新模組

FlexiTools 的核心是其模組化架構。創建一個新模組非常簡單。所有模組都應放在 modules/ 資料夾中。

1. 繼承基礎 `Module` 類別

您的新模組類別必須繼承自 ui.py 中定義的 Module 類別。

from ui import Module

class YourNewModule(Module):
    def __init__(self, master, shared_state, module_name="YourModule", gui_manager=None):
        super().__init__(master, shared_state, module_name, gui_manager)
        # 在這裡初始化您的變數
        self.create_ui()
        self.update_language() # 確保在UI建立後呼叫

2. 實現 `create_ui` 方法

這是在模組框架內建立所有 UI 元素（按鈕、輸入框等）的地方。所有 UI 元件都應該被放置在 self.frame 內。

def create_ui(self):
    # self.frame 是您的模組的主容器
    main_content_frame = ttk.Frame(self.frame, padding="10")
    main_content_frame.pack(expand=True, fill=tk.BOTH)

    self.my_label = ttk.Label(main_content_frame, text="Hello, Module!")
    self.my_label.pack()

    self.my_button = ttk.Button(main_content_frame, text="Click Me", command=self.my_action)
    self.my_button.pack()

3. 支援多語言

為了支援多語言，請實現 update_language 方法。使用 self.tr("key", "default_text") 來獲取翻譯後的文字。

def update_language(self):
    super().update_language() # 更新模組標題
    if not getattr(self, 'my_label', None): return

    self.my_label.config(text=self.tr("module_yourmodule_greeting", "Hello, Module!"))
    self.my_button.config(text=self.tr("module_yourmodule_button", "Click Me"))

接著，您需要在 locales/ 資料夾下的對應 JSON 檔案中添加您的翻譯鍵值對。

程式碼風格

我們力求保持程式碼庫的乾淨和一致。請在提交程式碼前：

  • 遵循 PEP 8 程式碼風格指南。
  • 模仿現有模組的程式碼結構和命名約定。
  • 為複雜的邏輯添加簡潔的註釋，解釋 *為什麼* 這樣做，而不是 *做什麼*。
  • 確保您的程式碼在所有主要平台上都能良好運行。

提交您的貢獻

我們使用 GitHub Flow。請遵循以下步驟來提交您的變更：

  1. Fork 我們的儲存庫。
  2. 為您的變更創建一個新的 分支 (git checkout -b feature/your-new-feature)。
  3. 進行您的變更並 Commit。請撰寫清晰的提交訊息。
  4. 將您的分支推送到您的 Fork (git push origin feature/your-new-feature)。
  5. 開啟一個 Pull Request 到我們的主分支。

您的貢獻將被審查，我們可能會要求一些修改。一旦審查通過，您的變更將被合併。非常感謝您的努力！
